CI now checks that committed notebook outputs match what the notebook currently produces, not merely that it runs. The docs render notebooks with `nb_execution_mode = "off"`, so stale outputs are published verbatim and look authoritative — the site once advertised a `2.1.1` version banner and true-positive rates of 0.997, both artifacts of code that had since been fixed. Each notebook is executed on an in-memory copy and compared cell by cell; nothing is written and no diff is produced, a mismatch simply fails and names the cell. Numbers are compared with a 1e-4 relative tolerance so last-digit drift between the machine that committed the outputs and the CI runner does not fail the build, while everything that is not a number must match exactly. by @parulgupta1004
